**Bootloader** 是职责描述：上电后初始化硬件（时钟、DDR、串口）、把内核从存储介质搬进内存、跳转执行。uboot是bootloader的一种
emmc是硬盘，DDR是内存，SRAM是cpu的内部缓存（比如L1,L2,L3)。
ROM 指的是 BootROM（片内启动 ROM）——SoC 出厂时就固化在芯片内部的一小段只读代码
## ==🔴**ARMv7架构板子的启动流程**==
1.上电后 ROM Code 解析 IVT、执行 DCD 初始化 DDR，把 U-Boot 从 eMMC 加载到 DDR 运行；
2.U-Boot 初始化串口 /eMMC/ 网络等外设，再把 **kernel 和 dtb 都**从 eMMC 加载到 DDR，通过 r2 寄存器把 dtb 地址传给 kernel 并跳转；
3.kernel 解析 dtb 建立设备树、probe 各驱动、挂载 rootfs、拉起 init，系统才算启动完成。
ROM/DCD的分工：
- ROM/DCD：只初始化了**最小必要硬件**（时钟、DDR），够把 U-Boot 跑起来就行
- U-Boot：初始化**它自己需要的**外设 —— 串口控制台、eMMC/SD 驱动、网络、USB 等

### 6.问题
#### 问题一：为什么 U-Boot 需要重定位？
**U-Boot 重定位，是把自身从 BootROM 加载的位置复制到 RAM 顶端，并按 `.rel.dyn` 表修正所有绝对地址，同时重建 gd、栈、malloc 堆、BSS 和异常向量表。**

目的有三个： ① **腾出低端连续内存**给内核镜像、设备树、initrd，避免后续加载时覆盖 U-Boot 自身（最主要）； ② **获得完整可写的 C 运行环境**，包括可写的 data/bss、足够大的栈和堆； ③ **与加载地址解耦**，同一份镜像可在任意地址运行，同时获得更高执行速度，并能安全地擦写启动介质（saveenv、自我升级）。
```
0xA0000000  RAM 顶端  ┌─────────────────────┐
                     │ MMU/视频等预留区     │
0x9FF8_xxxx          ├─────────────────────┤
                     │  U-Boot 代码+数据+BSS │ ← relocaddr，搬到这里
                     ├─────────────────────┤
                     │  malloc 堆           │
                     │  bd_info / gd_t      │
                     │  栈                  │
                     ├─────────────────────┤
        ……           │   （大片空闲内存）    │
0x83000000           │  ← dtb 放这里         │
0x80800000           │  ← zImage 放这里      │
0x80000000  RAM 起点 └─────────────────────┘
```
#### 问题二：为什么重定位之前要执行 board_init_f()，重定位之后又要执行 board_init_r()？
board_init_f的作用是：需要为后续 U-Boot 在 DRAM 中运行做好准备。
- 初始化必要的硬件。
    
- 获取或配置 DRAM 信息。
    
- 计算完整 U-Boot 的重定位地址。
    
- 计算重定位后的栈地址。
    
- 规划新的 GD 地址。
    
- 将后续启动需要的信息保存到当前 GD 中。
`board_init_r` 负责在新的运行环境下完成后续初始化。
